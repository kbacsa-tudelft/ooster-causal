Zeeland storm surge, Jan 1976 — interpolated flood-risk map (5-min model)

A continuous risk surface over the real OpenStreetMap basemap (drag/zoom like any map): each gauge contributes a soft gaussian impulse, so the surface fades to nothing away from every gauge instead of extrapolating - blue is calm, red is at or above each gauge's own POT/EVT flood threshold (risk = |observed − predicted| / threshold, so every gauge's very different natural variability is normalized onto the same 0-1+ scale). Each gauge's contribution lingers and decays with a 3-hour half-life rather than switching on and off hour to hour, so a real spike fades out gradually instead of spiking and vanishing. Drag the slider or press play to scrub through the event.

calm  →  at/above flood threshold
Model: zeeland_flood_eval_5min (5-min resample, CUTS+ causal discovery + hold-out 1-step prediction). Risk = max(|observed − predicted| this hour, previous risk × decay) / that gauge's own POT threshold (cm), decay = 0.5^(1/3) per hour (3-hour half-life) - a peak-hold-with-decay filter, computed once at build time from the trained checkpoint's saved residual z-scores and POT/EVT threshold refit at risk=0.001 / initial_level=0.99 / num_candidates=100 (the best-F1 point from sweep_pot_params.py). The surface is a gaussian-kernel interpolation across the 40 gauges (of 77 total) with enough validation data to fit a threshold at all - the model only ever had Zeeland's own gauges to work with, so risk away from them is extrapolated, not measured. Event window (1976-01-03 14:00 → 1976-01-05 18:00) shown as a red band on the slider track. Basemap: OpenStreetMap tiles, rendered live by openstreetmap.org - a hand-assembled vector coastline (an earlier version of this page) kept producing small but real errors at specific spots (confirmed directly, e.g. a visibly wrong rounded edge near the Oosterscheldekering barrier traced straight back to upstream OSM coastline-way data, not a bug in the assembly), so this switched to the same real-tile approach the project's causal-map exports already use, trading the claude.ai artifact link's ability to show it (its security policy blocks loading remote tile images) for actual map accuracy in the committed file.
