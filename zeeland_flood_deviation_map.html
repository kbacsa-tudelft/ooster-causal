Zeeland storm surge, Jan 1976 — interpolated flood-risk map (5-min model)

A continuous risk surface across Zeeland and the surrounding Dutch/Belgian border area, interpolated (inverse-distance-weighted) between every gauge over the real OpenStreetMap basemap (drag/zoom like any map) - transparent where calm, solid red at or above each gauge's own POT/EVT flood threshold (risk = |observed − predicted| / threshold, so every gauge's very different natural variability is normalized onto the same 0-1+ scale). The surface is computed well beyond Zeeland's own border so it can fade out on its own - most of that wider area reads as ~0 anyway, since every gauge the model has is in Zeeland - rather than ending in a visible box edge. Each gauge's contribution lingers and decays with a 3-hour half-life rather than switching on and off hour to hour, so a real spike fades out gradually instead of spiking and vanishing. The slider moves through the model's own native 5-minute resolution - every step is a real, measured timestep, not an interpolated one; autoplay advances in slightly larger jumps to keep a full playthrough watchable, but dragging the slider by hand reaches every real 5-minute reading. Drag the slider or press play to scrub through the event.

Model: zeeland_flood_eval_5min (5-min resample, CUTS+ causal discovery + hold-out 1-step prediction). Risk = max(|observed − predicted| this hour, previous risk × decay) / that gauge's own POT threshold (cm), decay = 0.5^(1/36) per 5-min step (3-hour half-life) - a peak-hold-with-decay filter, computed once at build time from the trained checkpoint's saved residual z-scores and POT/EVT threshold refit at risk=0.001 / initial_level=0.99 / num_candidates=100 (the best-F1 point from sweep_pot_params.py). The surface is an inverse-distance-weighted interpolation across the 40 gauges (of 77 total) with enough validation data to fit a threshold at all, computed over a bounding box around this stretch of the Netherlands and Belgium (not just Zeeland's own tight bbox) so it can fade out on its own before reaching an edge - a small constant background weight blended into the IDW sum is what makes distance from every gauge actually pull risk toward 0 instead of the plain-IDW tendency to keep echoing whichever gauge is nearest, however far; confirmed with a real test render before shipping. The model only ever had gauges in Zeeland, so risk away from there is extrapolated, not measured - which in practice mostly reads as transparent. Event window (1976-01-03 14:00 → 1976-01-05 18:00) shown as a red band on the slider track. Basemap: Esri's free World Light/Dark Gray Base tiles (no key required) - osm.org's own tile server actively 403s embedded pages like this one (its usage policy is personal/low-volume only), and CARTO's free anonymous tiles turned out to need a key too, just rendered as an "API KEY REQUIRED" watermark baked into the tile image rather than an HTTP error - both confirmed directly before landing on Esri. A hand-assembled vector coastline (an earlier version of this page) kept producing small but real errors at specific spots (confirmed directly, e.g. a visibly wrong rounded edge near the Oosterscheldekering barrier traced straight back to upstream OSM coastline-way data, not a bug in the assembly), so this switched to real map tiles instead, trading the claude.ai artifact link's ability to show it (its security policy blocks loading remote tile images) for actual map accuracy in the committed file.
